[01] Reconciliation

Dental Payment Reconciliation

Which open dollars are real misses, and which retry would charge someone twice?

What I built

I built this practice project for this portfolio. seed.py loads one synthetic dental week into SQLite. sql/exceptions.sql is the queue: duplicate ERA or card posts, cash on the wrong patient, an insurance short pay with no denial, a refund larger than the original payment, and the attempt-level blocks. investigate.py prints that queue and writes exception_queue.csv. It does not change payments. reprocess_plan.py is a dry run that writes a plan file. --execute inserts a row into reprocess_queue with status planned and does not create a second payment. The script checks the idempotency key again before it writes, and it stops if the posted-payment count changes.

A patient card or ACH attempt is eligible only when the key was never posted, no refund is requested or issued on the claim, the attempt is pending or failed and older than 3 days, and the amount equals the open balance. An insurance short pay stays on an appeal list. It is not a card retry.

How to run

From the repo root:

python3 payment-exceptions/python/seed.py
python3 payment-exceptions/python/investigate.py
python3 payment-exceptions/python/reprocess_plan.py

Python 3 standard library only. The figures above are the synthetic week, not a live ledger.

[02] Choice ops

Did this disbursement already move, or is it safe to send again?

Same four breaks I already chase on money coming in, pointed at money going out. I pull the timeline, I refuse anything that would pay twice, and I only write a plan row.

What the code does

seed.py rebuilds a synthetic disbursement ledger, a webhook log, and one client batch file. investigate_failure.py sets the ledger row next to the event log. Pass an id, such as DSP-7001, when I want one timeline.

reprocess.py is a dry run. It keeps the rows that are safe to plan and blocks the rest. --execute inserts plan rows only. The disbursement count stays 20. A second execute inserts 0.

reconcile_batch.py compares the Northwind file with settled disbursements. classify_webhook.py turns a processor code into a label. A label is not a send.

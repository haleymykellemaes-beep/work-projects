SQL & Python Operations Toolkit

What do I copy the next time a number does not tie?

These synthetic examples show how I would investigate failed payments in a technical operations role.

What I built

I built five practice examples for this portfolio, each with a consistent project structure: a README, sql/query.sql, and python/run.py. The synthetic rows are written in the script. Python 3 standard library and sqlite only. Each script loads those rows, runs the query, prints a short result, and does not call a network. The dental ledger and the disbursement project stay in their own folders.

[01]

Investigate

One id. sql/query.sql returns the ledger row and then the event log, in time order. The script states the mismatch in one sentence and does not update either side.

The planted row is PAY-1042. The ledger says failed. The last webhook says settled. Both amounts are $1,250.00.

python3 patterns/investigate/python/run.py

[02]

Repair

Dry run by default. sql/query.sql flags a settled idempotency key. The script refuses that attempt. --execute inserts a plan row and does not insert a payment. It checks that the posted-payment count did not change.

ATT-11 / KEY-OPEN is planned. ATT-12 / KEY-SETTLED is refused because that key is already on a settled payment.

python3 patterns/repair/python/run.py
python3 patterns/repair/python/run.py --execute

[03]

Reconcile

Two sources. sql/query.sql labels each trace matched, missing left, missing right, amount mismatch, or duplicate key. The script prints the label and the dollars. It does not change either source.

Five synthetic traces: TR-1001 $100 matched; TR-1002 $200 missing on the right; TR-1003 $150 missing on the left; TR-1004 ledger $300 vs file $280; TR-1005 $64 once on the ledger and twice in the file.

python3 patterns/reconcile/python/run.py

[04]

Classify

sql/query.sql looks up a code. A code that is not on the map escalates. The script prints labels only. It does not retry, edit a recipient, or write a payment.

The map in this example: 96 and 91 retry, R01 wait, R03 fix data, settled do not retry. The sample code XX escalates.

python3 patterns/classify/python/run.py

Notes · Source

[05]

Variance

sql/query.sql subtracts expected from actual and flags a row when the absolute gap is larger than its tolerance. The script prints the dollars. It does not post an adjustment, and it does not compute a failure rate.

Three lines: collections $12,400 expected vs $12,110 actual, tolerance $50; fees $860 vs $860, tolerance $25; hours priced at $45, $1,800 vs $1,620, tolerance $45. Collections and hours flag. Fees do not.

python3 patterns/variance/python/run.py

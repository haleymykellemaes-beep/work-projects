[03] Pattern library

What do I copy the next time a number does not tie?

Every problem gets the same four files. I use them on failed payments at Choice Digital, and on an ordinary business total that will not match.

The four files

  • README.md — the question, the inputs, the control, and how to run.
  • sql/query.sql — the check, readable on its own.
  • python/run.py — loads a few synthetic rows, runs the check, prints a short result, exits 0.
  • The rows — written in the script. Standard library and sqlite only.

These are skeletons. The full dental ledger and the disbursement drills stay in their own folders.

[01]

Investigate

One entity id. The system of record on one side, the event log on the other. Say the mismatch in one sentence.

Use it when someone hands me a payment id and the row and the webhook disagree.

python3 patterns/investigate/python/run.py

Notes · Source

[02]

Repair

Dry run by default. Refuse the attempt if its idempotency key is already settled. --execute writes a plan row only. It does not create a payment.

Use it before a retry, a reprocess, or any second send.

python3 patterns/repair/python/run.py
python3 patterns/repair/python/run.py --execute

Notes · Source

[03]

Reconcile

Two sources. Report missing left, missing right, amount mismatch, and a duplicate key.

Use it on a batch file against the settled ledger, or any two extracts that should tie.

python3 patterns/reconcile/python/run.py

Notes · Source

[04]

Classify

Map a code to an action: retry, do not retry, fix data, wait, or escalate. No live side effects.

Use it when a webhook or a return code needs a label before anyone touches the payment.

python3 patterns/classify/python/run.py

Notes · Source

[05]

Variance

Expected versus actual for a business total: collections, fees, and hours priced in dollars. Flag a row outside its tolerance and print the dollars.

Use it when the tie-out is not a payment id. A week of collections, a fee bill, a labor total.

python3 patterns/variance/python/run.py
